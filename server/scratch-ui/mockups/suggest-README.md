# 목업 — 다듬기 제안

```bash
python3 -m http.server 4399 --directory server/scratch-ui
# → http://localhost:4399/mockups/suggest.html
```

실제 `app.css` 를 걸어서 색과 버튼이 운영 화면과 같다.

## 무엇을 보여주나

글 짜기 화면에 **「다듬기」 보기**를 하나 더 둔다 (쓰기 · 개요 · 미리보기 옆). 다 쓰고
한 번 훑는 자리다.

- 제안은 **목록**이다. 누르기 전에는 글자가 안 바뀐다
- **「이대로 고치기」** — 대체어가 분명한 것만 준다
- **「짚어만 둠」** — 기계가 대신 쓸 수 없는 것 (시적 아사이드 같은 것). 고치기 버튼이 없다
- **「그냥 두기」** — 그 메모에서 다시 안 뜬다
- **「이 규칙 안 볼래」** — 규칙째 끈다. 아래 목록에서 되살린다
- **저장을 막지 않는다.** 머리말이 매번 「하나도 안 고쳐도 저장된다」 고 말한다

## 제안이 어디서 오나 — 모델을 안 쓴다

이 화면은 **AI 없이 글을 쓰려고** 만든 것이다. 모델이 문장을 고쳐주면 그 취지가 무너진다.

그래서 규칙은 전부 **`CLAUDE.md` 에서 가져왔다** — 1번(어미 표), 2-1번(AI 음역 표 · 시적
아사이드 · 자기지시 메타), 3번(다음 글 예고), 메모 표기 규약(`?` `!` `+`), 그리고
`check-markdown.mjs` 가 잡는 틸드 취소선.

그건 작성자가 **직접 적어둔 「이건 AI 티다」 목록**이다. 적용하는 것은 AI 가 문장을 쓰는 게
아니라 **작성자의 기준을 기계가 짚어주는 것**이다. 토큰도 네트워크도 안 쓴다.

**모델은 이번 목업에 없다.** 넣으려면 서버에 Anthropic API 키가 새로 생기고(지금 자격
증명은 scratch 저장소 하나에 닿는 GitHub 토큰뿐이다), 작성자가 쓰는 문장이 외부로 나간다.
별도 결정이어야 한다 — 규칙만으로 모자란 게 드러난 뒤에 본다.

## 왜 별도 보기인가

왼쪽 덩어리 본문은 `<textarea>` 라 **안쪽에 밑줄을 못 긋는다.** 쓰는 중에 끼어드는 대신
다 쓰고 한 번 보는 자리로 뒀다 — 「강제하지 않는다」와도 맞는다.

## 랄프 루프에서 잡힌 것

[ralph 기록](../../../.orchestration/reports/suggest/ralph.md) 에 네 바퀴를 남겼다
(이 경로는 `.gitignore` 대상이라 로컬에만 있다). 요지는 이렇다.

1. **1차 — 「고치기」가 글을 망가뜨렸다.** 틸드 규칙이 `~1.5~2주~` 에서 `~1.5~` 만 잡아
   「약 1.5」로 바꿔 `약 1.52주~` 가 됐다. 제안을 받아들이면 글이 더 나빠지는 상태였다
2. **1차 — 같은 자리에 카드가 둘.** `예상됨` 이 두 규칙에 걸렸다. 겹치면 하나만 남긴다
3. **1차 — 순서가 규칙별이었다.** 원고는 위에서 아래로 읽는다 → 덩어리 · 줄 · 열 순
4. **3차 — 규칙을 꺼도 개수가 안 줄었다.** 가려져 있던 규칙이 같은 자리에 올라왔다 →
   어미 규칙 둘을 하나로 합쳤다
5. **4차 — 전부 넘긴 뒤 「걸리는 게 없다」 고 했다.** 고친 게 아니라 넘긴 것이다 →
   「N개를 그냥 뒀다」 로

## 아직 안 정한 것

- **오름차순 목록 · 맞춤법.** 지금 규칙은 전부 작성자가 적어둔 기준이다. 일반 맞춤법
  (띄어쓰기 · 오탈자)은 사전이 필요하고, 그건 규칙이 아니라 데이터다. 넣을지 별도 판단
- **어디까지 고칠 수 있게 하나.** 지금은 한 자리씩이다. 「전부 고치기」 를 둘지
- **보관.** 「그냥 두기」를 메모 단위로 기억할지(지금 목업은 새로 고치면 잊는다)

## 🚫 만들지 않았다 (2026-10-31)

작성자가 「초안 결정」을 실제로 써본 뒤 정했다. 두 가지가 드러났다.

1. **글을 다 쓰고 나서 문장을 다듬지 않는다.** 하는 일은 **논리 순서 정리**뿐이다.
   다듬을 자리가 없으니 다듬기를 돕는 기능도 설 자리가 없다
2. **「소제목 덩어리」 모델이 오히려 자유도를 줄였다.** 작성자의 글은 소제목 *안에* 또
   헤더와 목록이 들어간다. 칸이 구조를 도와주는 게 아니라 **구조를 두 번 만들게** 했다

2번은 이 기능이 아니라 **「초안 결정」 자체에 대한 지적**이다. 기능이 모자란 게 아니라
기본 단위를 잘못 잡았다 — 글의 단위가 「소제목 하나 + 그 아래 산문」이라고 가정했는데
실제 글은 그렇게 안 생겼다.

작성자가 쓰는 방식은 이렇게 돌아갔다.

```
웹 에디터에서 메모 작성 → 「완성」 → Claude CLI 가 scratch 를 읽는다
  → 내용적으로 빠진 부분만 짚는다 → 고친다 → 발행
```

**이 폴더의 파일은 기록이다. 할 일 목록이 아니다.**
