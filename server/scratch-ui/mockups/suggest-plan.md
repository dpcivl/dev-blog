> # 🚫 만들지 않는다 (2026-10-31)
>
> 작성자가 「초안 결정」을 실제로 써본 뒤 **제안 기능은 필요 없다**고 정했다.
> 글을 다 쓰고 나서 **문장을 다듬지 않기 때문**이다 — 하는 일은 논리 순서 정리뿐이다.
> 다듬을 자리가 없으니 다듬기를 돕는 기능도 설 자리가 없다.
>
> 아래는 그때까지 한 설계 기록이다. **할 일 목록이 아니다.**

# 구현 계획 — 다듬기 제안

목업: [suggest.html](suggest.html) · 설계 배경은 [suggest-README.md](suggest-README.md)

4단계다. **1·2단계만 끝나도 쓸 수 있다.** 3단계가 「오타」 쪽이고, 4단계는 문서다.

---

## 0. 목업을 보고 정한 것

목업을 보여주고 나서 남아 있던 셋을 이렇게 정한다. 다르게 하고 싶으면 **구현 전에** 말해야
한다 — 1단계가 시작되면 되돌리는 비용이 는다.

| 열려 있던 것 | 정한 것 | 왜 |
| --- | --- | --- |
| 일반 맞춤법(오타)을 넣나 | **사전을 들이지 않는다. OS 에 맡긴다** (3단계) | 아래 참고 |
| 「전부 고치기」를 두나 | **안 둔다** | 한꺼번에 적용하면 「내 글을 누가 고쳐놨다」 가 된다. 이 기능이 피하려던 느낌이 바로 그것이다. 한 자리씩이어야 **고칠 때마다 작성자의 결정**이 된다. 지겨워지면 그때 둔다 |
| 「그냥 두기」를 기억하나 | **기억한다. 메모 단위로** | 안 기억하면 열 때마다 같은 제안이 다시 뜬다. 그건 재촉이고, 「강제하지 않는다」를 어긴다 |

## 1. 규칙 엔진 — `src/suggest.js` (새 파일)

**DOM 을 건드리지 않는 순수 모듈로 만든다.** 미리보기 렌더러(`blocksOf`)가 DOM 노드를 직접
만들어서 vitest 로 못 덮은 전례가 있다 — 같은 실수를 되풀이하지 않는다.

```js
export const RULES = [ { id, name, why, find, fix } … ];
export function suggest(sections, { off = new Set(), dismissed = new Set() } = {});
//   → [{ key, ruleId, si, li, at, text, to, line, where }]
```

**규칙은 전부 `CLAUDE.md` 에서 온다.** 목업의 여덟 개로 시작한다 — 메모 어미 · 영어 음역 ·
자기지시 메타 · 시적 아사이드 · 다음 글 예고 · 숫자 범위 물결 · 앞머리 물결 · 메모 표기.
`fix` 가 `null` 이면 「짚어만 둠」이다.

**지켜야 하는 두 가지.** 목업의 랄프 루프에서 실제로 걸린 것들이다.

- **겹치는 제안은 하나만 남긴다.** 먼저 잡은 쪽이 이긴다. 둘을 다 보여주면 어느 쪽을
  누를지 사람이 판단해야 하는데, 그게 이 기능이 덜어주려던 일이다
- **정렬은 덩어리 → 줄 → 열.** 원고는 위에서 아래로 읽는다

**`fix` 는 맞은 범위를 통째로 바꾼다.** 목업 1차에서 틸드 규칙이 `~1.5~2주~` 의 앞쪽만 잡아
`약 1.52주~` 를 만들었다. **제안을 받아들였더니 글이 더 나빠지는 것**이 이 기능에서 제일
나쁜 실패다. 규칙마다 「고친 뒤 결과」를 테스트로 고정한다.

### 테스트 (vitest, `tests/suggest.test.mjs`)

- 규칙마다 **걸리는 문장 · 안 걸리는 문장**
- **`fix` 를 적용한 뒤의 줄 전체**를 단언한다. 바뀐 조각만 보지 않는다
- 겹침 제거 · 정렬
- `off` · `dismissed` 가 걸러지는지
- 한 줄에 같은 규칙이 여러 번 걸릴 때 (`lastIndex` 무한 루프 방지 — 빈 매치 처리)
- **코드 블록 안은 건드리지 않는다** — 목업에 없는 구멍이다. ` ``` ` 안의 `~x~` 나
  영어 음역은 코드일 수 있다. `check-markdown.mjs` 의 `detectAccidentalStrikethrough` 가
  같은 이유로 코드를 지우고 본다

## 2. 다듬기 보기 — 화면

- `index.html` 의 보기 묶음에 **「다듬기」** 를 넣는다 (쓰기 · 개요 · 미리보기 옆)
- `.compose[data-view="polish"]` 로 가른다. 기존 셋과 같은 방식
- 카드는 `compose.js` 가 그린다

### ⚠️ `innerHTML` 을 쓰지 마라

목업은 `innerHTML` + `esc()` 로 그렸다. **실제 구현에서는 쓰지 않는다.**

`src/` 에는 `innerHTML` 이 **한 줄도 없다** (보안 점검에서 확인됐다). 메모 본문이 그대로
들어가는 자리라 `textContent` 로만 넣는 규칙을 지켜왔다. 인용 줄은 세 조각(앞 · 맞은 것 ·
뒤)을 각각 `createElement` + `textContent` 로 만들어 붙인다.

### 「강제하지 않는다」를 지키는 것들

| 요구 | 어떻게 |
| --- | --- |
| 누르기 전에 안 바뀐다 | 제안은 목록이다. `fix` 는 버튼 누를 때만 돈다 |
| 무시해도 된다 | 「그냥 두기」 → `dismissed` 에 넣고 보관 (아래) |
| 재촉하지 않는다 | **저장을 막지 않는다.** 보기 단추에 개수 뱃지를 달지 않는다 |
| 규칙이 틀릴 수 있다 | 규칙째 끄기 + 되살리기 |
| 기계가 못 고치는 것 | `fix === null` 이면 고치기 버튼을 **안 만든다** |

### 보관

`scratch:compose:<name>` 에 이미 `{sections, active, meta, pulled, base, at}` 를 담고 있다.
거기에 **`dismissed`(배열)와 `off`(배열)** 를 더한다.

- `dismissed` 는 **메모 단위**다. 다른 메모로 가면 새로 본다
- `off` 는 **메모를 넘어 공통**이어야 자연스럽다 → `scratch:rules-off` 로 따로 둔다
- localStorage 접근은 **전부 try/catch** (사생활 보호 모드에서 막힌다)

### 키는 줄 내용까지 넣는다

목업은 `${si}:${li}:${at}:${ruleId}` 로 키를 만든다. **글을 고치면 줄 번호가 밀려서
엉뚱한 제안이 「그냥 두기」된 것으로 보인다.** 키에 맞은 글자(`text`)를 넣고, 줄 번호가
밀려도 같은 글자면 같은 제안으로 본다.

## 3. 오타 — 사전을 들이지 않는다

`compose.js:347` 이 본문 칸의 맞춤법 검사를 **일부러 꺼놨다.**

```js
body.spellcheck = false;
```

**원고 칸에서는 켠다.** 그러면 OS 와 브라우저의 맞춤법 검사가 붙는다 — 빨간 물결, 오른쪽
클릭으로 고치기, 작성자가 사전에 추가한 낱말까지. **사전을 들이지 않고, 네트워크도 안
쓰고, 코드도 한 줄이다.**

| 칸 | spellcheck | 왜 |
| --- | --- | --- |
| 초안 (오른쪽, CodeMirror) | **끈다 (지금대로)** | 읽기 전용 참고 글이다. 물결이 그어져봐야 할 게 없다 |
| 메모 (초안 모드) | **끈다 (지금대로)** | 거친 메모다. 코드 · 영어 · 약어가 섞여 물결 천지가 된다 |
| **원고 본문 (덩어리)** | **켠다 (바꾼다)** | 여기가 발행될 문장이다 |

갈라두는 게 원칙이다 — **거친 글은 그냥 두고, 발행될 글만 본다.**

**정직하게 적어둘 것.** 한국어 맞춤법 품질은 OS 와 브라우저에 달렸다. macOS 는 시스템
사전이 붙어 쓸 만하고, Windows 크롬의 한국어 지원은 그만 못하다. 작성자가 두 기기를 쓰므로
**기기마다 다르게 보인다.** 이건 우리가 못 고친다 — 그래서 「오타를 잡아준다」고 약속하지
않고 「OS 가 잡아주게 열어둔다」로 적는다.

사전을 직접 들이는 길(hunspell-ko 등)은 **안 간다.** 수 MB 짜리 데이터를 화면에 실어야
하고, 이 저장소에서 그만한 무게를 질 이유가 아직 없다. 규칙 엔진으로 모자란 게 드러난 뒤에
다시 본다.

## 순서와 위험

```
1 규칙 엔진  →  2 다듬기 보기  →  3 맞춤법  →  4 문서
                 ↑ 여기까지면 쓸 수 있다
```

| 위험 | 어떻게 |
| --- | --- |
| **제안을 받아들였더니 글이 더 나빠진다** | `fix` 적용 뒤 **줄 전체**를 테스트로 고정 (목업 1차에서 실제로 났다) |
| 같은 자리에 제안이 둘 | 겹침 제거. 먼저 잡은 쪽이 이긴다 |
| 글을 고치면 「그냥 두기」가 엉뚱한 데 붙는다 | 키에 맞은 글자를 넣는다 |
| 코드 블록 안의 글자를 짚는다 | 코드를 지우고 본다 (`check-markdown.mjs` 와 같은 방식) |
| 규칙이 `CLAUDE.md` 와 갈라진다 | 4단계에서 「같이 고친다」를 적어둔다 |
| 재촉으로 느껴진다 | 저장을 안 막고, 뱃지를 안 달고, 끌 수 있게 한다 |
| 맞춤법이 기기마다 다르다 | 못 고친다. **약속하지 않고 적어둔다** |
