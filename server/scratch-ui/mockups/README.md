# scratch 화면 목업

구현 전에 흐름을 눌러보려고 만든 화면이다. **배포에 실리지 않는다** —
`deploy/README.md` 의 설치 절차는 `index.html` · `app.js` · `app.css` 세 개만 올린다.

## 여는 법

```bash
python3 -m http.server 4399 --directory server/scratch-ui
# → http://localhost:4399/mockups/compose.html
```

`.claude/launch.json` 에 `scratch-ui` 로 올려둬서 Claude Code 의 미리보기로도 열린다.
파일을 그냥 더블클릭해도 되지만, 그때는 `../app.css` 가 상대경로로 붙어야 하므로
폴더 구조를 유지한 채로 열어야 한다.

## compose.html — 초안 결정 → 구조 다시 짜기 (2026-10-30)

지금 화면은 메모 칸 하나다. 이 목업은 거기에 **「초안 결정」** 을 눌렀을 때를 그렸다.
초안이 **오른쪽**으로 가서 읽기 전용이 되고, **왼쪽**에 글을 짜는 칸이 열린다.

**왼쪽은 글을 대신 써주는 칸이 아니라 구조를 짜는 칸이다.** 문장은 전부 사람이 쓴다.

- 글은 **소제목 덩어리**의 목록이다. 덩어리를 더하고 · 순서를 바꾸고 · 지운다
- 뼈대 프리셋 한 번에 「상황 → 시도 → 원인 → 회고」 네 덩어리가 선다
- 오른쪽 줄의 `◀ 가져오기` 는 **지금 고른 덩어리**로 들어간다. 옮기는 건 **원문 그대로**다
  — 문장을 만들어내지 않는다. 초안의 소제목 줄만 덩어리 제목 자리로 간다
- 가져간 줄은 오른쪽에서 흐려지고 `n / m 줄 옮김` 이 찬다. **초안을 다 썼는지**가 보인다
- 보기 세 가지 — **쓰기** · **개요**(소제목과 문단·글자 수만) · **미리보기**(읽히는지 본다)
- 「원고로 저장」은 scratch 저장소에 `posts/<slug>.md` 로 커밋한다

### 발행 검사가 없는 이유

한 번 넣었다가 뺐다 (2026-10-30 작성자 결정). 보안 스크럽 · `pubDatetime` · 미렌더
mermaid · 이미지 경로는 **공개 저장소로 나갈 때** 하는 일인데, 이 경로에서는 그 단계가
아직 Claude 세션에 남아 있다. 여기서 한 번 더 하면 두 곳에서 같은 걸 검사하게 된다.

`pubDatetime` 이 frontmatter 에 없는 것도 같은 이유다 — 발행하는 쪽에서 「그때의 과거
시각」으로 박아야 `isPublishTimePassed` 에 안 걸린다.

### 발행 경로 — B 안으로 정했다

서버 토큰은 fine-grained 로 **scratch 저장소 Contents 만** 닿는다. 그래서 웹에서 바로
블로그에 올리지 않고, scratch 저장소에 **원고**로 둔다. `deploy/README.md` 의
「서버가 뚫려도 블로그에 글이 올라가지 않는다」가 그대로 사실로 남는다.

가짜 데이터로 돌고 서버에 닿지 않는다. 아무것도 저장·발행되지 않는다.
