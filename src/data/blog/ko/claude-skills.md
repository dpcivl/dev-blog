**이 글은 AI를 사용하여 정리하지 않은 글입니다.**

## 배경
- AI 엔지니어로 일하기 위해서는 어떤 AI 툴을 사용할 수 있는지 도구에 대한 이해를 하고 있어야 한다고 생각함

## 클로드 skills
- 클로드가 꺼내 보는 업무 매뉴얼
- 클로드 skills는 메타데이터, 지침, 리소스로 이루어짐
  - 메타데이터는 skills에 대한 한 줄 요약임
  - 메타데이터가 유저의 요청과 관련 있으면 지침을 펼쳐봄
  - 지침을 보고 사용해야겠다 싶으면 작업 중에 리소스를 사용하는 식

## 일단 먼저 사용해보자
- 요즘 AI 파이프라인 만드는 것에 재미들리고 있음
  - 그래서 3가지 skills를 만들고 이걸 호출해서 기능 구현을 해보려고 함
  - 구현하다가 보안 skill을 추가로 만들게 됨

## 어떻게 세팅하는가
- 클로드에서 카드로 만들어달라고 하기
- 직접 파일 만들어서 클로드에 스킬 등록하기
- ~/.claude/skills 위치에 파일을 두기만 하면 됨

## 설계 skill
- 설계 단계에서는 RPI와 랄프 루프를 사용하고자 함
- 목표는 기능 정의에 대한 목업 산출물
- 클로드 세션에서 기술을 설명하면 이런 식으로 만들어줌
  - 내가 생각한 기능대로 소스에 들어가있는지 확인하는 작업 이후 저장
![](/assets/posts/claude-skills/01-hi-dev-plan-card.webp)
- /hi-dev-plan을 만들었고 RPI를 통해 설계 문서인 design.md를 만듦
- skills는 매뉴얼일 뿐 프로그램이 아니기 때문에 랄프 루프를 클로드가 계속 실행하게 할 수는 없음
  - 그래서 design.md 생성까지만 하는 것으로 하고 랄프 루프는 SKILL.md를 직접 둬서 `claude -p`로 실행되게 하는 걸로 정함
- 카드로 저장한 skill은 프로젝트 디렉토리에 있는 게 아니라 계정에 저장됨
  - 프로젝트 디렉토리에서 같이 관리하는 게 좋은데 skills 폴더에 같이 넣으면 같은 이름의 스킬이 두 개가 되므로 소스를 관리하는 폴더로 만들어서 마크다운 안 내용만 복제해주면 됨 

## 목업 skill
- 랄프 루프로 목업을 만들기 위한 skill을 만들기 위해서 디렉토리를 세팅함
  - vscode에서 폴더 생성을 진행했으며, 그러지 않을 경우에 .claude 같은 폴더는 예약어 때문에 폴더를 생성할 수 없을 수도 있음
 

```
---
name: hi-dev-mockup
description: Builds an HTML mockup from docs/design.md one step per run, tracking progress in docs/mockup-progress.md. Run by the Ralph loop script or with /hi-dev-mockup for a single step.
disable-model-invocation: true
allowed-tools: Read Write Edit Bash(bash .claude/skills/hi-dev-mockup/scripts/check_ids.sh)
---
```
- 초기 SKILL.md 내용은 이랬음
  - description을 보고 claude가 스킬을 쓸지 말지 정함
  - 그런데 disable-model-invocation이 true로 되어있기 때문에 유저가 직접 호출하여 skill을 사용해야 함
  - 위의 --- 사이에 내용을 이름표라고 부름


```
# hi-dev-mockup: 목업 단계 매뉴얼 (랄프 루프 1회분)

이 매뉴얼은 **한 번 실행에 한 걸음만** 진행한다. 반복은 바깥의 `scripts/ralph.sh`가 맡는다.
매 실행은 이전 대화를 기억하지 못하므로, 기억은 전부 `docs/mockup-progress.md` 파일에 남긴다.

## 입력과 출력
- 입력: `docs/design.md` (hi-dev-plan이 만든 설계 문서. 수정하지 않는다)
- 출력: `mockup/index.html` (목업), `docs/mockup-progress.md` (진행 기록)
```
- 이름표 밑에 작성한 내용임
  - claude에서 skill을 꺼냈을 때 읽는 매뉴얼 본문 내용
- 반복은 랄프 루프 스크립트 맡는다고 명시함으로써 claude가 반복하지 않게 함

````
## 매 실행 순서

### 1. 상황 파악
- `docs/design.md`를 읽는다. 없으면 "docs/design.md가 없습니다. hi-dev-plan을 먼저 실행하세요."라고 말하고 멈춘다.
- `docs/mockup-progress.md`를 읽는다. 없으면 첫 실행이므로 아래 양식으로 만든다. design.md의 화면 ID(S1, S2…)와 기능 ID(F1, F2…)를 하나도 빠짐없이 옮긴다.

```
# 목업 진행 기록

## 할 일
- [ ] S1: (화면 이름)
- [ ] F1: (기능 이름) - 완료 기준: (design.md의 완료 기준)

## 실행 기록
```
````
- 위의 내용은 design.md가 없는 경우 환각을 일으키지 않고 즉각 멈추게 함
- 목업 진행 중 끊긴 경우를 대비하여 mockup-progress.md를 읽게 함

```
### 2. 한 걸음 작업
- 체크되지 않은 항목 중 **맨 위 하나만** 고른다. 화면(S)을 기능(F)보다 먼저 한다.
- 그 항목만 `mockup/index.html`에 만들거나 고친다. 다른 항목은 건드리지 않는다.
- 목업 규칙:
  - HTML 파일 하나, 외부 라이브러리 없이 HTML/CSS/JavaScript만 쓴다.
  - 데이터는 그럴듯한 한국어 더미 데이터로 채운다. 서버 연동은 하지 않고 흉내만 낸다.
  - 화면 영역 시작에 `<!-- S1 -->`, 기능 요소 근처에 `<!-- F2 -->`처럼 ID 주석을 단다.
```
- 랄프 루프 특성 상 한 번에 하나씩만 구현하면서 계속 루프를 돌며 기능을 완성한다

```
### 3. 검증
- `bash .claude/skills/hi-dev-mockup/scripts/check_ids.sh`를 실행해 ID 주석이 빠진 항목을 확인한다.
- 방금 작업한 항목의 완료 기준을 HTML 코드와 대조한다.
- 둘 다 통과하면 그 항목을 `[x]`로 체크한다. 통과하지 못하면 체크하지 않고 이유를 기록한다. 다음 실행이 이어서 고친다.
```
- 검증은 check_ids.sh 스크립트에서 진행함

```
### 4. 기록
- `## 실행 기록` 맨 아래에 한 줄을 추가한다. 예: `- 3회차: F2 목록 정렬 추가, 검증 통과`
- 모든 항목이 체크되었고 check_ids.sh가 통과하면, 파일 맨 마지막 줄에 정확히 `STATUS: DONE`을 쓴다.
- 그 외에는 `STATUS: DONE`을 절대 쓰지 않는다.
```
- 각 루프마다 실행한 기록을 실행 기록에 적어둠
- STATUS: DONE이 되면 목업 생성이 완료되었다고 판단

```
## 하지 말 것
- 한 번에 여러 항목을 처리하지 않는다.
- design.md에 없는 기능을 추가하지 않는다. 필요해 보이면 실행 기록에 "제안:"으로 남긴다.
- 검증하지 않고 체크하지 않는다.
```
- 앞에서 나온 부분을 하지 말 것으로 다시 얘기함
  - 반복해서 적는 이유는 내용이 길어질 경우 누락될 수 있기 때문이라고 함

- 이런 식으로 구성이 되면 SKILL.md가 준비된 것이고 문서에서 얘기한 스크립트를 경로에 준비해둬야 함
- 클로드에서 카드로 만들어달라고 하고 저장하는 건 금방 만들어지지만 SKILL.md를 직접 세팅하는 건 이런 식으로 작성이 필요함

- 맨 처음 목업을 만들 때는 /hi-dev-mockup을 호출해서 만들면 되지만 기능이 여러 개인 경우에 한 번에 목업을 완성시켜서 보고 싶다면 bash 명령어를 사용하여 ralph.sh를 직접 실행해야 했음
  - skill로는 매번 새 대화를 시작할 수 없고 랄프 루프를 사용해서 `claude -p`가 새 대화를 시작하게 하기 위해서임
  - 매뉴얼은 skill, 반복은 스크립트로

## 구현 skill
- 구현은 AI 오케스트레이션으로 진행함
- AI 오케스트레이션의 구성은 이전에 에이전트 파이프라인 실험하면서 사용했던 스펙으로 진행
- 이 단계에서 SKILL.md 파일의 작성 방법 뿐만 아니라 .claude 폴더 안에 agents 폴더를 만들면서 서브에이전트에 대한 마크다운 파일도 직접 작성해봤음
- SKILL.md의 내용은 길어서 내용이 맞는지만 검토하고 넘겼음
  - agents 폴더에서 만든 서브에이전트들을 어떻게 사용할 건지에 대한 내용들을 작성했음
  - AI 오케스트레이션을 어떻게 구성하고 워크플로우가 어떻게 되는지에 대한 자료를 넘겨줘서 SKILL.md를 작성하게 함

## 보안 skill
- 외부에서 공격하는 skill을 따로 만듦
  - 만든 서비스를 docker로 띄운 것을 공격하여 취약점을 발견하는 것이 목표
- fable로 공격을 하는 것을 기본으로 하되, fable은 보안 쪽으로 구현을 하다가 막히는 경우가 잦아서 계속 막히면 opus로 변경하도록 함
- 만약 취약점을 발견하면 재현할 수 있도록 재현 방법까지 정리하여 보고하게 함
- 걱정되는 것은 맥북 환경에서 도커 서비스로 공격을 시도하는 것이기 때문에 갑자기 공격 대상을 바꿔버려서 문제가 생기는 거 아닌지에 대한 걱정이 듦
  - 그래서 지금은 구현하지 않고 세팅만 해둠
 - attacker 대신에 audit을 만듦
   - 공격하는 대신 코드 전체를 읽어 보안 관점에서 수정해야 할 것이 없는지 확인
   - 구현 단계에서 만들었던 security 에이전트를 여러 개 사용하여 확인

## Skill로 서비스 만들어보기

  - 나중에 블로그에 빅데이터분석기사 후기를 올릴 건데 거기에 사용할 자료로 모으고 있음

## 정리
- 클로드 skill은 표준화할 수 있는 반복 작업에 유용함
  - 같은 형식의 산출물을 받거나, 비슷한 작업을 수행하거나 하는 식
- skill을 먼저 정의하고 필요할 때마다 불러서 사용

## 알게된 문제점
- 목업 구현할 때 랄프 루프를 사용했는데 STATUS:DONE을 잘못 읽어서 목업 구현이 일부만 됐음에도 멈추는 경우를 발견
- /hi-dev-impl과 같이 skill을 직접 호출하면 하나만 구현하고 끝나버림
  - 그냥 설계된 기능 전부 스킬을 사용해서 구현해달라고 하면 끝까지 구현하고 나서 검토할 수 있음 

## 후속 진행 방향
- 이번에 만든 SKILL을 통해서 여러 프로젝트에서 내 파이프라인을 이용하여 기능 구현이 되도록 할 수 있으면 좋겠음
  - 기존 프로젝트에 해당 파이프라인을 적용해서 기능 추가를 해보려고 함
  - 웹 개발이 아닌 다양한 분야에서도 돌아갈 수 있는 generic한 파이프라인으로 개선
- 파일을 클로드에 올려서 skill로 적용하는 건 해보지 못했음. 추후에 시도할 예정.
