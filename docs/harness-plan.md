# 블로그 저장소 하네스 설계안

작성 2026-11-14 · 상태: **검토 대기** (작성자 확인 전, 구현 안 함)

계기는 NVIDIA AI Day Seoul 에서 들은 발표다. 에이전트·하네스를 쓰는 것이
디폴트이고, 남은 문제는 보안이며 그 보안은 **권한 세팅**으로 푼다는 내용이었다.
안전장치를 확실히 해둘수록 맡길 수 있는 영역이 넓어진다.

이 문서는 그 「권한 세팅」을 이 저장소에 어떻게 넣을지 적은 것이다.

## 1. 지금 무엇이 있고 무엇이 없나

조사해봤다.

| 하네스 층 | 상태 | 근거 |
| --- | --- | --- |
| 역할 나눈 에이전트 7개 | **있음** | `.claude/agents/` |
| 오케스트레이션 절차 · 사람 게이트 | **있음** | `.claude/orchestration.md` |
| 검사 명령 4종 | **있음** (손으로 돌림) | `check:md` · `links` · `test` · `test:py` |
| 권한 목록 (허용 / 확인 / 차단) | **없음** | `.claude/settings.json` 이 존재하지 않는다 |
| 훅 (도구 실행 전후 자동 개입) | **없음** | 같은 파일이 없다 |
| git 훅 | **없음** | `.git/hooks/` 가 비어 있다 |

**그래서 지금은 전부 「내가 읽고 지키는」 구조다.** 지침과 절차는 촘촘한데
강제하는 것이 없다. 2026-09-06 에 집 공인 IP 가 push 된 사고가 이 구조의 결과다
— 「집 IP 는 공개 저장소에 올리지 말 것」이라고 적어둔 문서 자체가 올라갔다.

### 검사 스크립트의 빈 칸

`check:md` 가 실제로 잡는 것은 셋이다.

1. 미렌더 mermaid 블록
2. 우발적 strikethrough (`~1.5~2주` 같은 tilde 오파싱)
3. **공인 IP 주소** ← 사고 후에 추가됨

CLAUDE.md 보안 절에는 이것 말고도 막아야 할 패턴이 적혀 있다 — 32자리 이상
hex · `eyJ` 로 시작하는 JWT · `sk-` · `sk_live_` · `ghp_` · `github_pat_` ·
`*.supabase.co` 같은 고유 인스턴스 도메인. **이 중 코드로 막힌 것은 없다.**
IP 만 사고가 나서 추가됐고 나머지는 글로만 남아 있다.

### 선례 — 번역 킬스위치

이 저장소에는 이미 하네스가 하나 있었다. 2026-08-25 에 EN 번역을 중단할 때
CLAUDE.md 에 배너를 달았는데, 닷새 뒤 **코드에도 차단을 걸었다.** 이유가
주석에 적혀 있다 — *"지침만으로는 세션이 바뀌면 잊고 호출할 수 있어서."*

지침 한 겹으로는 안 된다는 판단이 그때 이미 나왔다. 이 설계안은 그 판단을
저장소 전체로 넓히는 것이다. (번역은 2026-11-14 에 다시 켰고 킬스위치는
제거했다.)

## 2. 세 층으로 짓는다

```
① 권한 목록   — 무엇을 묻지 않고 하고, 무엇을 묻고, 무엇을 아예 못 하나
② 훅          — 그 경계를 넘으려는 순간 자동으로 개입한다
③ 검사 확장   — 지침에만 있는 보안 패턴을 코드로 옮긴다
```

①만 넣으면 「위험한 명령」은 막지만 **글 내용**은 못 본다. ③만 넣으면 검사를
건너뛰면 그대로 나간다. ②가 둘을 묶는다.

### 층 ① — 권한 목록

세 칸으로 가른다. 아래는 초안이고, 쓰면서 늘린다.

| 칸 | 넣을 것 | 왜 |
| --- | --- | --- |
| **묻지 않음** (allow) | 읽기 전용 git (`status` · `diff` · `log` · `show`) · `ls` · `cat` · `grep` · `find` · `date` · 검사 명령 4종 · `pnpm mermaid:render` · `pnpm images:webp` · `astro build` | 지금 매번 뜨는 확인 창의 대부분이 이것들이다. 되돌릴 게 없다 |
| **묻는다** (ask) | `git push` · `git commit` · `gh` 전체 · `rm` · `mv` · scratch 저장소 쓰기 | 외부로 나가거나 파일이 사라진다 |
| **아예 못 함** (deny) | `.env*` 읽기 · `git push --force` · `git reset --hard` · `rm -rf` · `deploy/` 키 파일 접근 · `mermaid:gc` | 되돌릴 수 없거나 과거에 사고가 난 것 |

deny 칸의 근거를 하나씩 적는다.

- **`.env*` 읽기** — Anthropic API 키가 있다. 내가 읽을 이유가 없다. 번역
  스크립트는 프로세스가 직접 읽으니 이 차단과 무관하다
- **`mermaid:gc`** — 2026-08-30 에 **사용 중인 SVG 를 전부 삭제한 적이 있다.**
  고아 판정이 `<img>` 참조를 못 세서 그랬다. 스크립트는 고쳤지만 이 명령은
  내가 알아서 돌릴 것이 아니다
- **`git push --force` · `reset --hard`** — 다른 기기(Windows)와 두 저장소를
  오가는 구조라 히스토리를 되감으면 복구가 어렵다

### 층 ② — 훅

도구를 실행하기 **전**과 **후**에 끼어드는 자리다. 넷을 제안한다.

| 훅 | 언제 | 무엇을 하나 | 막는 사고 |
| --- | --- | --- | --- |
| **발행 게이트** | `git push` · `git commit` 직전 | `check:md` 를 돌린다. 실패하면 **명령을 거절한다** | 미렌더 mermaid 가 코드 블록째 발행되는 것 · 공인 IP · 시크릿 |
| **글 저장 검사** | 블로그 글 · `deploy/` 문서를 쓰거나 고친 **직후** | 그 파일만 보안 검사한다. 걸리면 즉시 알린다 | push 까지 안 가고 그 자리에서 잡힌다 |
| **세션 시작 루틴** | 세션 시작 | 두 저장소 pull · 준비됨 메모 확인 | 내가 루틴을 잊는 것. 지금은 지침으로만 돈다 |
| **발행 전 사람 확인** | 발행 커밋 직전 | 무엇을 발행하는지 한 줄로 보여주고 멈춘다 | 작성자 확인 없이 글이 나가는 것 |

**발행 게이트가 이 설계의 중심이다.** 지금 `check:md` 는 내가 기억해서
돌리는 명령이고, 안 돌려도 빌드와 링크 검사는 통과한다 — 조용히 나간다.
훅으로 옮기면 건너뛸 방법이 없다.

### 층 ③ — 검사 확장

`check:md` 에 시크릿 패턴을 더한다. CLAUDE.md 에 이미 목록이 있으니 새로
정할 것은 없고, 글로 있는 것을 코드로 옮기는 일이다.

| 추가할 패턴 | 예 |
| --- | --- |
| 알려진 키 접두사 | `sk-` · `sk_live_` · `sk_test_` · `ghp_` · `gho_` · `github_pat_` |
| JWT | `eyJ` 로 시작하는 토큰 |
| 32자리 이상 hex | 커밋 해시는 예외로 둔다 |
| 고유 인스턴스 도메인 | `*.supabase.co` · `*.vercel.app` |
| 20자 이상 base64 (`=` padding) | 오탐이 많을 자리라 경고만 |

**오탐 주의.** 2026-09-23 에 User-Agent 예시가 IP 검사에 걸려 막힌 적이 있다.
base64 와 hex 는 글에 정상적으로 등장할 수 있으니 처음에는 **경고만** 내고,
접두사와 JWT 처럼 오탐이 거의 없는 것만 `exit 1` 로 막는다.

## 3. 번역 축 (2026-11-14 추가)

이 설계안을 처음 쓸 때 번역은 **중단 상태**였다. 그래서 발행 게이트를 KO
기준으로만 짰다. 같은 날 번역을 다시 켰으니 축이 하나 빠진 설계였다.

### 지금 무엇이 비어 있나

조사해봤다.

| 질문 | 답 |
| --- | --- |
| KO/EN 짝이 맞는지 누가 보나 | **아무도 안 본다.** `check:md` 는 짝을 보지 않는다 |
| 번역 품질 검증기(`validate.mjs`)는 언제 도나 | **번역하는 순간에만** 돈다 |
| 그 검증기를 따로 돌릴 수 있나 | **없다.** 단독 실행 명령이 없어서 재번역하는 수밖에 없다 |
| 검증에 걸리면 번역이 막히나 | **안 막힌다.** 경고만 찍고 파일은 쓴다 |
| KO 를 고친 뒤 EN 이 안 따라온 것을 누가 보나 | **아무도 안 본다** |

마지막 칸이 이미 사고로 나와 있다.

```
KO 가 EN 보다 나중에 커밋된 글 — 4편
  blog-beyond-astropaper-what-i-added     KO 가 88일 최신
  fems-project-log-01                     KO 가  7일 최신
  (나머지 2편은 같은 날이라 순서 차이일 수 있다)
```

**88일 밀린 글이 하필 CLAUDE.md 7번에 「갱신하면 EN 재번역」이라고 적어둔
그 글이다.** 이 글은 KO 와 EN 이 서로 다른 해시의 다이어그램을 참조하고 있다
— 그림까지 갈라졌다.

구조가 2026-09-06 IP 사고와 같다. 지침에 적어둔 바로 그것이 지침만 있어서
어긋났다.

### 넣을 검사 여섯

| 검사 | 무엇을 보나 | 걸리면 |
| --- | --- | --- |
| **짝 검사** | KO 글에 같은 slug 의 EN 이 있는지 (draft 는 제외) | 커밋을 **거절한다** |
| **갈라짐 검사** | KO 가 EN 보다 나중에 고쳐졌는지 | 경고한다. 재번역 명령을 같이 찍는다 |
| **페어 검증 단독 실행** | `validate.mjs` 를 번역 없이 돌린다 | 발행 게이트가 이것을 부른다 |
| **한국어 잔존 검사** | EN 글 본문에 한글이 남아 있는지 | 경고한다 (태그·고유명사는 예외) |
| **EN 그림 한국어 검사** | EN 글이 참조하는 SVG 의 **보이는 텍스트(`<p>`)** 에 한글이 있는지 | 경고한다 |
| **원본 보존 검사** | 참조되는 SVG 해시에 짝이 되는 `.mmd` 가 있는지 | 경고한다. 없으면 다시 렌더할 수 없다 |

**짝 검사만 게이트로 막는다.** 나머지는 경고다 — 갈라짐은 작성자가 일부러
미룰 수 있고, 한국어 잔존은 고유명사 때문에 오탐이 난다.

### 뒤의 둘은 2026-11-14 에 추가됐다

같은 날 「길 2」(번역을 렌더보다 앞으로 당기고 원본을 보존하는 것)를 구현한
뒤에 생긴 검사다. 처음 설계안에는 없었다 — 그때는 `.mmd` 보존도 순서
의존성도 없었으니 검사할 대상이 아예 없었다.

**기능을 넣으면 그 기능이 지켜지는지 보는 검사가 따라붙는다.** 이번이 그
예다. 순서를 바꿔 고쳤더니 **「순서를 틀릴 수 있다」는 새 실패 경로**가
생겼다.

| 새 실패 경로 | 어떻게 되나 |
| --- | --- |
| 렌더를 번역보다 먼저 돌린다 | 번역할 원본이 사라져 EN 이 한국어 그림을 참조한다. **빌드도 링크 검사도 통과한다** |
| `.mmd` 를 커밋에서 빠뜨린다 | 다른 기기에서 다시 렌더할 재료가 없다. 당장은 아무 증상이 없다 |

둘 다 조용히 지나간다는 점이 2026-09-06 IP 사고와 같다.

**순서 자체를 보지 않고 결과를 본다.** 「렌더를 먼저 돌렸나」를 알아내려면
실행 이력을 봐야 하는데 그건 남지 않는다. 대신 **EN 글이 참조하는 SVG 안에
한글이 있나**를 보면 순서를 틀렸을 때의 결과가 그대로 잡힌다. 한국어가 없는
다이어그램은 KO/EN 이 같은 해시를 공유해도 정상이라, 해시 비교보다 이쪽이
오탐이 적다.

짝 검사를 막는 이유는 CLAUDE.md 가 「자주 하는 실수」 1번으로 **KO 만 커밋**을
꼽아뒀기 때문이다. 짝이 깨지면 언어 스위치가 홈으로 fallback 되고 방문자가
이탈한다. 지금은 이것을 막는 장치가 없다.

### EN 그림 검사는 보이는 텍스트만 본다

SVG 안의 한글을 통째로 세면 **노드 id 가 걸린다.** 실제로 그런 경우가 나왔다.

```
id="mermaid-13-세션"          ← 서브그래프 id 가 한글
<span class="nodeLabel"><p>Session — The server remembers</p></span>   ← 라벨은 영어
```

id 는 화면에 나타나지 않고, 바꾸면 그 id 를 쓰는 엣지 선언과 어긋난다.
그래서 이 검사는 `<p>` 안의 보이는 텍스트만 본다.

**2026-11-14 소급 작업 결과 이 검사는 현재 0건이다** — EN 글 22편의
다이어그램 31개를 영어로 바꿨다. 검사는 앞으로 순서를 틀렸을 때를 위해 둔다.

### 출력 로그 번역 — 검증기가 잡지만 판단은 사람이 한다

2026-11-14 번역에서 나왔다. Neo4j 실행 출력이 이렇게 번역됐다.

```
KO: 가열로 (유사도: 0.8145) - 관련 알람: ['온도 초과']
EN: Furnace (similarity: 0.8145) - Related alarms: ['Temperature Exceeded']
```

숫자는 보존됐지만 **그 DB 에 실제로 든 값은 한국어다.** CLAUDE.md 어조
가이드의 「코드/명령/로그는 그대로 인용 — 작성자가 실제로 본 화면을 그대로
재현」과 어긋난다.

검증기는 이것을 `codeBlocks content differs` 로 잡아낸다. 다만 주석 번역도
같은 경고로 잡히기 때문에 **기계가 둘을 못 가른다.** 그래서 이 항목은
게이트로 막지 않고, 번역 프롬프트 쪽에서 「언어 태그가 없거나 `txt` 인 블록은
원문 유지」 같은 규칙으로 줄이는 편이 맞다. 작성자 판단이 남는 자리다.

### EN 다이어그램은 하네스가 아니라 기능이다

EN 글이 참조하는 SVG 는 KO 와 같은 파일이다. `alt` 만 영어로 번역되고
**그림 속 글자는 한국어로 남는다.** 영어 독자는 영어 설명을 읽고 한국어
그림을 본다.

이것을 고치는 일은 검사도 제약도 아니다 — mermaid 원본을 EN 으로 번역해서
따로 렌더하고, EN 글이 그 해시를 참조하게 만드는 **기능 구현**이다. 하네스
설계에 섞지 않는다.

**이 기능은 2026-11-14 에 구현했다** (커밋 `e450bd2`). 번역이 mermaid 라벨을
영어로 바꾸고, 렌더가 `ko/` 와 `en/` 을 각각 훑어 두 SVG 를 만들고, 원본이
`src/data/mermaid/<hash>.mmd` 에 남는다. **앞으로 쓰는 글에만 적용된다** —
이미 발행된 24편은 원본이 없어 소급되지 않는다.

하네스가 맡는 부분은 위 표의 뒤 두 줄이다 — **EN 글이 한국어 그림을 참조하고
있다는 사실**과 **원본이 보존됐는지**를 드러내는 것. 24편을 고치는 것은 SVG
안의 글자를 직접 번역하는 별도 작업이고, 하네스는 그 24편이 몇 편인지
집계해줄 뿐이다.

## 4. 이렇게 달라진다 — 통과/차단 예시

설정을 넣은 뒤 같은 상황에서 무엇이 벌어지는지 적었다. 이게 목업에 해당한다.

| 상황 | 지금 | 하네스 적용 후 |
| --- | --- | --- |
| `git status` 를 돌린다 | 확인 창이 뜬다 | 그냥 돈다 |
| 글에 mermaid 블록을 넣고 렌더를 잊은 채 push | **통과한다.** 코드 블록이 발행된다 | 게이트가 거절한다 |
| 글에 공인 IP 가 들어간 채 push | `check:md` 를 돌렸으면 잡히고, 안 돌렸으면 **통과한다** | 게이트가 거절한다 |
| 글에 `sk-ant-...` 가 섞여 있다 | **아무것도 안 잡는다** | 저장하는 즉시 알린다 |
| 내가 `cat .env` 를 시도한다 | 확인 창이 뜨고, 승인하면 키가 화면에 나온다 | 실행되지 않는다 |
| 내가 `mermaid:gc` 를 돌리려 한다 | 확인 창이 뜬다 | 실행되지 않는다 |
| 세션을 시작한다 | 내가 기억해서 pull 한다 | 자동으로 돈다 |
| 발행 커밋 직전 | 내가 바로 커밋한다 | 무엇을 발행하는지 보여주고 멈춘다 |
| KO 만 커밋하고 EN 을 빠뜨린다 | **통과한다.** 언어 스위치가 홈으로 fallback 된다 | 커밋이 거절된다 |
| KO 를 고치고 EN 재번역을 미룬다 | **아무도 모른다** (88일 사례) | 경고하고 재번역 명령을 찍는다 |
| EN 글에 한글이 남아 있다 | 아무것도 안 잡는다 | 경고한다 |
| 렌더를 번역보다 먼저 돌린다 | **통과한다.** EN 이 한국어 그림을 쓴다 | 경고한다 (SVG 안 한글로 잡는다) |
| `.mmd` 를 커밋에서 빠뜨린다 | **증상이 없다.** 나중에 재렌더가 막힌다 | 경고한다 |

## 5. 한계 — 이것이 못 막는 것

| 못 막는 것 | 무엇이 대신 막나 |
| --- | --- |
| 이미 push 된 시크릿 | 키 재발급. 마스킹은 소용없다 (git history · 캐시 · 스크래퍼) |
| 문장이 AI 티가 나는 것 | CLAUDE.md 2번 절과 작성자 확인. 기계가 볼 수 없다 |
| 초안에 없는 내용을 지어내는 것 | CLAUDE.md 9번 절. 같은 이유로 기계가 볼 수 없다 |
| 스크린샷 안의 시크릿 | 사람 눈. 이미지는 검사 대상이 아니다 |
| scratch 저장소에 적힌 시크릿 | 거기는 private 이라 발행 경로만 막으면 된다 |
| 공유 메모에 들어온 지시문 | 메모는 데이터로만 읽는다. 지금도 그렇다 |
| 번역문의 뜻이 틀린 것 | 사람 눈. 검사는 구조만 본다 (블록 수 · 링크 · 길이 비율) |
| 출력 로그 번역과 주석 번역의 구분 | 사람 판단. 기계는 같은 경고로만 본다 |
| EN 다이어그램 그림 속 한국어 | 기능 구현이 따로 필요하다. 검사는 집계만 한다 |

## 6. 짓는 순서

사고가 실제로 난 곳부터 간다.

1. **검사 확장** — 시크릿 패턴 + 짝 검사 + 갈라짐 검사를 기존 스크립트에
   더하고, 페어 검증을 단독 실행할 수 있게 한다. 혼자서도 쓸모가 있고
   되돌리기 쉽다
2. **발행 게이트** — 그 검사들을 push·commit 직전에 강제한다. 시크릿과
   짝 깨짐은 거절, 갈라짐과 한국어 잔존은 경고
3. **권한 목록** — 확인 창을 줄이고 차단 칸을 세운다
4. **나머지 훅** — 세션 루틴 · 글 저장 검사 · 발행 전 확인

1번과 2번만으로 사고 세 건이 막힌다 — 2026-09-06 IP 유출, 미렌더 mermaid
발행, KO 만 커밋. 3번은 편해지는 쪽이고, 4번은 잊는 것을 막는 쪽이다.

**번역 기능 쪽 과제는 이 순서에 넣지 않는다.** EN 다이어그램 렌더와 번역
프롬프트 규칙은 하네스가 아니라 파이프라인 개선이다.
