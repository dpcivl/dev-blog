# 포트폴리오 인테이크 — 프로젝트 정보 수집 템플릿

새 프로젝트를 `parkhyo.in` 포트폴리오 · 홈 · About 에 올릴 때 필요한 정보를 한 번에 모으는 문서.

**쓰는 방법**

1. 아래 **§1 붙여넣을 프롬프트** 를 그대로 복사해 **해당 프로젝트의 Claude 세션**에 붙여넣는다.
2. 그 세션이 §2 형식으로 답을 만들어 준다.
3. 그 답을 블로그 세션(이 저장소)에 가져와 붙여넣으면 포트폴리오 항목 · 카드 · About 반영까지 처리한다.

> **왜 이 방식인가**: 프로젝트 세션은 코드·커밋·로그를 직접 볼 수 있어서 수치와 기간을 추측 없이 확인할 수 있다. 블로그 세션은 그 저장소를 못 본다.

---

## §1 붙여넣을 프롬프트

````text
이 프로젝트를 개인 블로그(parkhyo.in)의 포트폴리오에 올리려고 합니다.
아래 항목을 채워주세요. **저장소·커밋·로그·설정 파일을 직접 확인해서** 답하고,
확인이 안 되는 항목은 비워두고 "확인 불가" 라고 적어주세요. 추측으로 채우지 마세요.

작성 원칙 (중요):
- **홍보 문구를 쓰지 마세요.** 사실만 적습니다. 형용사·비유·"~를 통해 ~를 실현" 같은 표현 금지.
- 설명이 필요한 자리는 **제가 실제로 한 일**을 동사 중심으로 적습니다.
- 수치는 **측정 조건을 반드시 함께** 적습니다. (랩/실측, 기기, 데이터셋, 기준값)
  예: "LCP 1.4초 (랩·throttling 기준 / 실측 2.3초)" — 조건 없는 수치는 쓸 수 없습니다.
- 시크릿 금지: API 키·토큰·비밀번호·DB 접속 문자열·비공개 URL·개인정보를 답변에
  절대 포함하지 마세요. 로그·에러 메시지를 인용할 때는 한 줄씩 확인하고 마스킹하세요.
  (이 블로그는 GitHub public + Vercel 공개 배포라 한 번 올라가면 회수 불가입니다.)

--- 채울 항목 ---

[1] 프로젝트명:
[2] 한 줄 정체 (무엇을 하는 것인가, 사실만):
[3] 종류: side(개인 프로젝트) / work(회사 업무) 중 하나:
[4] 상태: in-progress(진행 중) / completed(완성) / paused(중단) 중 하나:
[5] 기간: 시작 YYYY-MM (또는 YYYY-MM-DD). 종료됐으면 종료일도. 진행 중이면 "진행 중":
[6] 내 역할 (혼자 했는지, 팀이면 내가 맡은 범위. AI 페어 프로그래밍 썼으면 그것도):
[7] 기술 스택 (실제로 쓴 것만. 언어·프레임워크·인프라·하드웨어):
[8] 설명 (3~5문장. 무엇을 만들었고, 어떤 구조이고, 왜 그렇게 했는지. 사실 위주):

[9] 접속 가능한 링크 — **이게 이 프로젝트의 포트폴리오 게재 여부를 결정합니다**
    - 배포된 사이트/앱 URL (있으면):
    - 공개 GitHub 저장소 URL (있으면):
    - 없으면 "없음" 이라고 적어주세요.

[10] 대표 지표 1개 — 카드 우측에 큰 활자로 세울 값
     - 값 (예: "v0.3.2", "mAP 85.5%", "요청 288 → 3"):
     - 설명 + 측정 조건 (예: "2026-07-13 웹 PWA 배포 · example.com"):

[11] 측정된 성과 (최대 3개. 숫자로 말할 수 있는 것만. 없으면 "없음")
     - 값 / 설명+측정조건:
     - 값 / 설명+측정조건:
     - 값 / 설명+측정조건:

[12] work(회사 업무) 인 경우만 — 담당 업무를 항목별로
     - 항목명 / 실제로 한 일:
     (5개 정도. 회사명은 적지 마세요 — 블로그는 "이전 직장" 으로 통일합니다.)

[13] 스크린샷 · 영상 (있으면 파일 경로와 각각 무엇을 보여주는지):

[14] 블로그 글감 — 이건 포트폴리오가 아니라 글로 쓸 재료입니다
     - 5분 이상 막혔던 문제와 원인:
     - 고치려다 **못 고친 것**:
     - 처음 알게 된 것:
     - 되돌아보면 다르게 했을 결정:

[15] 이 프로젝트를 지금도 만지고 있나요? (About 의 "지금 하고 있는 것" 반영 여부):

[16] 위 항목 중 **제가 직접 쓴 문장을 그대로 옮긴 부분**이 있으면 표시해주세요.
     (블로그 발행 시 제 문장을 우선 쓰고, 없으면 비워두고 제가 직접 채웁니다.)
````

## §2 돌아올 답변 형식

프로젝트 세션이 위를 채우면 대략 이런 모양이 된다. 이걸 블로그 세션에 붙여넣으면 된다.

```yaml
# 이 블록이 그대로 src/data/portfolio/<slug>.md 의 frontmatter 가 된다
title: "프로젝트명 — 한 줄 정체"
type: side # side | work
status: in-progress # in-progress | completed | paused
period: "2026-08-01 ~"
role: "1인 개발 · AI 페어 프로그래밍"
techStack:
  - Next.js
  - PostgreSQL
description: "3~5문장. 사실 위주."
highlight:
  value: "v1.0.0"
  label: "2026-08-15 배포 · example.com"
outcomes:
  - value: "약 2km"
    label: "데이터 손실 시작 거리 (공원 도보 측정)"
responsibilities: # work 인 경우만
  - k: "항목명"
    v: "실제로 한 일"
links:
  demo: "https://example.com"
  github: "https://github.com/..."
gallery:
  - "/assets/portfolio/<slug>/01-home.webp"
order: 30
```

그리고 아래 세 덩어리를 텍스트로 함께:

- **글감** ([14] 항목) — 블로그 포스트 초안 재료
- **About 반영 여부** ([15])
- **작성자 본인 문장 표시** ([16])

## §3 블로그 쪽에서 자동으로 처리되는 것 (요청 불필요)

프로젝트 세션에 물어볼 필요 없는 항목들:

| 항목 | 처리 |
|---|---|
| `order` | 기존 항목들과의 상대 순서로 블로그 쪽에서 정함 |
| `relatedPosts` | 이 저장소의 글 슬러그라 블로그 쪽에서 연결 |
| `cover` / `gallery` 경로 | 파일만 주면 `public/assets/portfolio/<slug>/` 로 옮기고 이름 정리 + `pnpm images:webp` |
| 슬러그 | 제목에서 블로그 쪽에서 생성 |
| EN 번역 | `pnpm translate one <slug>` (포스트만. 포트폴리오는 KO 단일) |

## §4 게재 규칙 (수집 전에 알아둘 것)

1. **접속 가능한 사이트가 있는 프로젝트만 `/portfolio` 에 노출한다.** 저장소 링크만 있는 건
   `_` prefix 로 숨긴다 (파일은 보존 — [content.config.ts](../src/content.config.ts) 의 loader 가
   `**/[^_]*.md` 라 자동 제외).
2. **회사명은 비공개.** work 항목은 `company: "이전 직장"` 으로 통일.
3. **수치는 측정 조건과 함께.** 조건 없는 큰 숫자는 과장이 된다.
4. **종료 프로젝트는 삭제하지 않는다.** `period` 종료일 마감 → `status: paused` → 파일명 `_` prefix.
5. **카피는 작성자가 쓴다.** 히어로 문장·자기소개 문장은 Claude 가 대신 쓰지 않는다.
   사실 나열과 구조·정렬까지만 처리한다.
6. **`/portfolio` 는 unlisted** — `noIndex` + `data-pagefind-ignore` + 사이트 네비 미노출.
   URL 을 아는 사람만 접근한다.
