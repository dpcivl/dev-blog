`.claude/orchestration.md` 를 먼저 읽고 그 절차를 따른다.

## 받은 것

$ARGUMENTS

(계획서 경로와 단계. 안 적혀 있으면 **묻고 멈춘다.** 추측해서 시작하지 않는다)

## 진행

### 1단계 — 메인이 계획을 좁힌다

- 계획서에서 **이번 단계만** 읽는다
- 손댈 파일, 수용 기준, 운영 조건(두 기기 · 재시작 · CSP · 빈 값)을 적는다
- 쓰기 범위를 에이전트별로 배정한다
- 애매한 곳은 **해석 결정**으로 적어둔다 (나중에 「계획과 다른 점」의 기준이 된다)
- 체크포인트 커밋 (작업 전 상태)

### G1 — 사람 승인

보고 형식대로 낸다. **권장안을 붙이지 않는다.** 승인 전에는 코드를 고치지 않는다.

### 2~3단계 — 찾고 쓴다

- 계획이 파일을 이미 짚었으면 `explorer` 를 건너뛴다
- `implementer` 를 부른다. 지시에는 **경로와 읽을 절**을 적고 문서 내용을 붙이지 않는다
- 테스트 러너가 있으면 `test-writer` 를 동시에 부른다.
  **없으면 부르지 않는다** — 지금 이 저장소는 없다

### 4단계 — 결정론적 게이트 (메인이 직접)

```bash
pnpm lint && pnpm format:check && pnpm build && pnpm check:md && pnpm links
```

`server/scratch-ui/src/` 를 고쳤으면 `pnpm scratch:build` 를 먼저.
mermaid 를 넣었으면 `pnpm mermaid:render`.
**게이트를 통과하기 전에는 리뷰를 부르지 않는다.** 도구가 잡을 것을 사람 몫 모델에 맡기지 않는다.

### 5단계 — 리뷰 셋 (동시)

- `reviewer` 에게 **커밋 해시 범위**를 준다
- `qa` 에게 수용 기준 목록과 띄울 서버 이름을 준다
- `security` 는 **자격 증명 · 배포 · 외부 입력 · CSP · 공개 발행에 닿을 때만**

### 6단계 — 지적 통합

`.claude/orchestration.md` 의 자율 처리 규칙대로 판정한다.

- 재현된 실패는 major 이상
- 두 역할 이상이 지적하면 심각도와 무관하게 수정
- 수정 비용이 작은 minor 는 묶어서 함께 수정

수정은 **같은 에이전트를 `SendMessage` 로 이어 불러** 시킨다. 지시에 **결정까지** 담는다 —
무엇을, 어떤 문구로, 어디에. 반영하지 않을 지적도 이유와 함께 적는다.
재검토는 「해결 여부와 이번 diff 의 새 문제」로 좁힌다. 최대 5라운드.

### G2 — 커밋 전 확인

「진행할까요」로 묻지 않는다. **사람이 직접 확인할 항목을 체크리스트로** 낸다 —
화면 흐름 · 오류 화면 · 핵심 동작. 결과를 받은 뒤에 넘어간다.

### 7단계 — 문서와 커밋

- `doc-keeper` 를 부른다
- 메인이 커밋한다. **push 는 사람이 말할 때만**

## 멈춰야 할 때

- 계획서에 없는 설계 판단이 필요할 때
- 에이전트가 쓰기 범위를 벗어났을 때
- 게이트가 두 번 연속 같은 곳에서 깨질 때
- 비밀값이 커밋에 들어가려 할 때 (**재발급을 먼저 권한다**)

## 쓰지 않을 때

글 발행 · 메모 정리 · 오타 · 파일 하나짜리 수정. 고정 비용이 일보다 크다.
